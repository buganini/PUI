Python compatibility

The shared framework and PySide6 backend support Python 3.9. Shared and Qt regression suites pass on Python 3.9.24 with PySide6 6.7.2 on Linux; embedded-host integration and other platforms need separate validation. Optional backends can require newer Python: the supported Flet 1.0.4 runtime requires Python 3.10+. See Python 3.9 compatibility for installation and the repeatable make check-python39 baseline check.

The Qt test runtime is pinned to PySide6==6.7.2 in tests/requirements-python39.txt; make check-python39 rejects a different version.

Backend installation

Installation extras: QPUIQ[pyside6], QPUIQ[wx], QPUIQ[flet], and QPUIQ[textual]. For Tkinter, install plain QPUIQ with native Python/OS Tk support; QPUIQ[tkinter] adds no pip dependency. See installation.

Backend alignment status and pinned PySide6 baselines: wx, flet, tkinter, and Textual. Textual has native headless Views/Tabs checks; broader alignment and terminal validation remain pending. wx, Qt and Tk have native regression coverage; Flet has serialized Session checks and live web Table editing/scrolling checks. Recorded env/ runtimes are PySide6 6.12.0, Flet 1.0.4, Tk 8.6 and Textual 8.2.8. Progress documents list the remaining checks.

Imperative Dialogs

Web Information, Warning, Critical, Confirm and Prompt are imperative, blocking functions, not declarative nodes. Call them from application callbacks after startup. Confirm returns a bool; Prompt returns a string (possibly empty), or None on Cancel; alert helpers return None. The application callback waits for the native browser dialog, while a separate transport thread receives its answer. Other UI callbacks and timers wait until the call returns. Disconnect or takeover raises ConnectionError. The title is included in the message, because native browser dialogs have no custom window title or severity icons. Browser suppression rules still apply. See the Web reference. Pyodide does not implement these synchronous helpers.

wx and tkinter dialog helpers accept dir and the compatibility alias directory. File filters accept Qt form ("Images (*.png *.jpg);;All (*)") or wx form ("Images|*.png;*.jpg|All|*"). SaveFile(default=None, ...) splits the default path into directory and filename; an explicit directory overrides its directory. Tkinter uses native filedialog/messagebox/simpledialog. wx and tkinter cancellation returns None; PySide6 OpenDirectory currently returns an empty string.

Application and view classes

Classes are the recommended API. Import Application and PUIView from the selected backend. Implement content() to declare the UI; initialize local state in setup(), which runs once when the view is first built. Constructors can accept explicit parameters and must call super().__init__().

Application classes


class Example(Application):
    def content(self):
        with Window(title="Example"):
            Label("Hello")

Example().run()

Reusable view classes

On wx, import PUIView from PUI.wx to schedule reactive redraws on the wx GUI queue. Redraw bursts are coalesced; removed views ignore queued work. Native widgets are reused during reconciliation and destroyed with their owner. Removing or replacing a virtual subview destroys its native roots, including controls inside wx sizer layouts. Keyed moves preserve those controls.


class Counter(PUIView):
    def setup(self):
        self.state = State()
        self.state.count = 0

    def content(self):
        with HBox():
            Label(str(self.state.count))
            Button("+").click(self.increment)

    def increment(self, event):
        self.state.count += 1

Deprecated decorators

Each decorator emits DeprecationWarning at its use site when it is applied; creating instances and redrawing existing views do not repeat that warning. Use Python's -Wd option to show deprecation warnings during migration.

@PUI and @PUIApp are deprecated but remain available for existing code. Replace a decorated function with a PUIView or Application subclass and move its body into content(self). Move parameters into an explicit constructor, initialize persistent local state in setup(), and use member event handlers. For example, @PUI def Greeting(text) becomes:


class Greeting(PUIView):
    def __init__(self, text):
        super().__init__()
        self.text = text

    def content(self):
        Label(self.text)

Existing decorator argument forwarding, backend scheduling, and functools.wraps metadata remain supported during deprecation. inspect.signature() displays the builder signature and inspect.unwrap() returns the builder for source inspection. Calling the wrapper still creates a view/application; a builder's return annotation does not describe the wrapper's return value.

Callback Interface

All callback interfaces accept an event object as the first argument. Other args/kwargs will be passed through to the callback function. For example 

def button_cb(event, data):
    print(data)

Button("button").click(button_cb, 1)
will invoke 

button_cb(event, 1)
when the event is emitted.

Responsive / Adaptive Layout

PUI adapts declarations to container size across desktop, browser and terminal backends. Conditions read the nearest non-virtual parent's measured content area, not necessarily the window or the space remaining after siblings. A nested panel therefore responds to its own available area. See how this interacts with sizing.

Declare base settings first, then overrides with breakpoints from small to large. Width thresholds include the boundary; when several match, later declarations win, not necessarily the largest threshold. Resizing below a threshold rebuilds the declaration with its base settings. Initially the size is None, so wide overrides do not apply and visibility keeps its baseline. Each wide* / tWide* method checks its own threshold sequence per node. Descending thresholds log a warning even when the rule does not match; equal thresholds are allowed. Warnings include the declaration location and are deduplicated using a bounded 128-entry cache. Rules are never automatically sorted.

# Inside content(), with a backend imported as UI:
# Declare each method’s breakpoints from small to large.
with UI.VBox().layout(weight=1):
    UI.Label("Title").style(fontSize=14).wideStyle(
        600, fontSize=18,
    ).wideStyle(1000, fontSize=24).tStyle(
        fontWeight=FontWeight.Normal,
    ).tWideStyle(80, fontWeight=FontWeight.Bold)
    UI.Button("Save").layout(width=120).wideLayout(
        600, width=160, padding=8,
    ).tLayout(width=12).tWideLayout(80, width=18)
    with UI.HVBox(minWidth=600, tMinWidth=60):
        UI.Label("Name")
        UI.Label("Details").visible(False).wideVisible(600, True).tWideVisible(60, True)

Graphical thresholds and dimensions use logical pixels; Textual uses character cells, .tVisible(), .tWideLayout() and .tWideStyle(). HVBox/VHBox use tMinWidth/tMinHeight for their terminal thresholds. Graphical wide overrides do not apply to Textual, and terminal overrides do not apply to graphical backends.

Size observation starts lazily when needed. Backend layout reports a measurement, State notifies subscribers when it changes, and the view reruns content(). Rules are evaluated there in Python; there is no stored breakpoint table. Existing size State is retained across matched nodes, and identical measurements do not notify. For Web, see the browser/worker update path.

These modifiers do not change node keys. Native widgets can be retained, subject to backend behavior (including the Flet direction-switch limitation documented under HVBox). Overrides support the same properties and native limitations as ordinary layout/style; Textual does not control terminal font size. Extremely small containers may still overflow. See the Adaptive Layout cookbook for a runnable example and Common Modifiers for API signatures.

Nested expansion demand follows the shared layout policy: visible child priority ≥ 2 promotes its container to 2 on that axis, recursively, without inheriting the full priority or numeric weight. Fixed-axis dimensions and main-axis weight=0 block promotion.

Common Modifiers

Public APIs include inline type annotations and preserve concrete node types through method chaining. See type annotation coverage and development checks; dynamic State/native options remain permissive.

container.size() returns a binding to the container's measured content size: None before layout, then (width, height). It lazily creates internal ._state and starts observing native layout changes. Matched nodes inherit the same State during update(prev); removed containers release their observer. Reading .size().value in content() subscribes the view to changed dimensions. Graphical backends measure logical pixels. Textual uses .tsize() for character cells; .size() on Textual and .tsize() on graphical backends return a binding with value None without starting a measurement. It excludes native borders and content padding; layout margins lie outside it. Window(size=...) still specifies a preferred initial size, stored as preferred_size, independently of the measured .size() binding. Web and Pyodide ignore this desktop initial size and use the available browser viewport or mount-container space.

.visible(value) sets shared boolean visibility. .wideVisible(minWidth, value) overrides it when the nearest physical parent's content width is at least minWidth logical pixels, skipping virtual PUIViews. Textual ignores this pixel rule. .tVisible(value) overrides the shared boolean on Textual; .tVisible(None) restores inheritance. .tWideVisible(minWidth, value) applies the width rule in terminal cells. Other backends ignore both terminal modifiers.

Declare the baseline first, then width overrides. Matching rules apply in declaration order, like wideStyle/wideLayout. Unknown parent size leaves the baseline unchanged. Size observation uses ordinary State subscriptions and remains active while children are frozen. Conditions use the whole parent content area, not remaining sibling space; prefer an externally sized parent. The old min/max width/height arguments on visible and tVisible have been removed.

Label("Details").visible(False).wideVisible(600, True).tWideVisible(60, True)
Label("Compact").wideVisible(600, False).tWideVisible(60, False)
Label("Desktop only").tVisible(False)
Label("Terminal only").visible(False).tVisible(True)

.visible(value: bool) declaratively shows or hides an ordinary widget or layout. Hidden elements do not reserve layout space, including their padding/margin, and cannot receive normal user input. The node itself still updates. Effective hidden visibility, after any Textual override and matching width rules, also sets pui_frozen=True: existing children are retained without DOM synchronization, and children of an initially hidden node are not mounted. Independent PUIView updates inside a frozen subtree are deferred. Effective visible state clears the flag, and the subtree catches up to current State when synchronized. Timers/background work are not stopped. Parent content() still executes Python declarations; freezing skips child mounting/reconciliation, not arbitrary Python code in that parent. Read State in content(), for example Label("Hello").visible(self.state.show); the setters accept booleans, not bindings (.tVisible() also accepts None for inheritance). Omitting both modifiers restores the default visible state. Window, Tab, ComboBoxItem, TableNode and virtual PUIView visibility are outside this API's supported scope. An explicitly positioned Grid keeps the other children's declared coordinates. Flet retains Python controls but its client may reset cursor/scroll and other transient native state on reappearance. Textual uses display, not its space-preserving native visible property. See the Label cookbook for a State-driven toggle.

PUINode.pui_frozen: bool = False can also freeze child synchronization without hiding the node. Set it on the node returned by a declaration. Its own properties continue to update; removing the node still destroys the retained subtree. Unfreezing a directly modified retained node requires a normal view update. Each call to .visible(), or .tVisible() on Textual, sets this flag to the inverse of its effective visibility, including matching width overrides.

Textual ignores dimensional settings in .layout() and ignores .style(); graphical backends ignore .tLayout() and .tStyle(). Chain both to share a declaration across backends. Textual width/height and padding/margin use whole cells; padding/margin retain top/right/bottom/left ordering. Positive weights map to native fractional layout units. Textual inherits .layout(weight=...) unless .tLayout(weight=...) explicitly overrides it (including zero). Omitted terminal overrides restore native CSS defaults on the next declaration. .tStyle() accepts RGB integer colors and normal/bold font weight (numeric weights at least 600 use bold); font size and family are controlled by the terminal and are not parameters of .tStyle().

width/height are desired sizes that stop automatic expansion on the corresponding axis, not hard maximums. Positive weights and parent allocation still apply. minWidth/minHeight supply only minimum hints and never imply desired dimensions or stop expansion. Desired dimensions may also become minimum hints, using the larger value when both are supplied. See desired and minimum sizes for backend constraints and Canvas examples.

Widget sizing is automatic by default. PUI assigns each component a preferred size and axis-specific expansion behavior, then maps that policy to the selected backend's native layout system. A TextField expands horizontally but keeps its native height; a Spacer takes flexible space on its container's main axis. Exact dimensions depend on the toolkit, platform, font and theme.

Use .layout() for intentional overrides: width and height provide explicit dimensions or native size hints, weight controls participation in flexible space along the parent layout's main axis, and padding/margin add spacing. Most ordinary controls should not need explicit dimensions merely to fit their container.

State Transactions Across Threads

State objects, lists, dictionaries and bindings share one process-wide reentrant lock. Each supported API operation is synchronized; use with state: to protect a multi-step operation or read several fields consistently:

with state:
    state.count += 1
    state.rows.append(State({"count": state.count}))

Nested scopes batch all State changes on the current thread, including child containers, and release the lock at the outermost exit. Other threads wait even when accessing unrelated State objects. Keep scopes short: do not wait for I/O, threads or UI events while holding the lock.

Binding .change() callbacks run after unlocking, on the updating thread. Reentrant callback writes append notifications after those already queued on that thread. Pending redraws are coalesced per view and dispatched after the callback queue drains; mutations during redraw can schedule another notification round. Callbacks from different threads can run concurrently and have no global delivery-order guarantee. Callback code that accesses shared data must provide its own synchronization.

Callbacks receive the value recorded for each mutation; the current State may already contain a newer value. Structural collection callback values are shallow snapshots; referenced mutable children are not frozen. Exceptions release the lock and notify queued partial changes without rollback or suppressing the original exception. All queued observers are attempted if a callback raises an ordinary exception; the first observer error is raised after dispatch, or logged if the transaction body already raised. Bound setters and custom comparison/sort functions still run synchronously under the lock.

Iterators and dictionary keys(), values() and items() are shallow snapshots rather than live views. Hold with state: to read State children consistently, or use Unstate() to snapshot a State list/dictionary. Direct changes to a backing collection or ordinary mutable value bypass synchronization; use State(value, deep=True) or explicit State containers for nested data. State synchronization does not marshal native widget calls onto the UI thread or make an entire content() rebuild atomic.

Named State Subscriptions

state(key).ref(name) returns the same State binding and declares a named subscription during content(). Names are nonempty strings; use a namespace such as example.filters.symbol. Attribute, list-item and dictionary-item State bindings support this method. These subscriptions are separate from node references: PUI.ref(name) still looks up nodes only.

Each backend exposes a replaceable state_ref_publish(name, value) function. Web's default collects values for batched URL synchronization. PySide6, wx, Tkinter and Flet forward values to an AI supervisor when running as a managed child; otherwise their default is a no-op. Textual and Pyodide default to a no-op. Calls outside content() do not publish. See URL Options and State refs for Web initialization, ordering, subscription lifetime and URL encoding.

import PUI.PySide6 as UI

def publish(name, value):
    print(name, value)

UI.state_ref_publish = publish

Assign the callback on the backend module, not to a locally imported function name. Every State .ref() declaration in that backend, including existing and nested views, looks up the current callback. It runs synchronously during content(), receives the original Python value, and may run again with an unchanged value on another rebuild. Reactive lists/dictionaries are passed as State containers; reading their entries in the callback records nested dependencies. Keep callbacks short and do not mutate State during view construction. To extend the default behavior, save default_publish = UI.state_ref_publish before replacing it and call default_publish(name, value) from the replacement.

Named Node References

node.ref(name) declares a nonempty, fixed string name and returns the node. After a successful update, PUI.ref(name) returns node.__pui_binder__(), whose default implementation returns a binder with .node storing the node that created it. Every backend exports the same lookup function: PUI.PySide6.ref is PUI.ref, and likewise for wx, Tkinter, Flet, Textual, Web and Pyodide. The registry is process-local, is not reactive State, and must be accessed on the UI thread. Names must be unique among live nodes, including across applications in one process. Use an application/component namespace, such as cookbook.refs.tabs; the dot is a naming convention, not a separate registry scope. The registry is internal; use ref(name) for lookup. PUI.refs is the helper module, not the registry dictionary.

import PUI
import PUI.PySide6 as UI

# In content():
with UI.Window(title="Example").ref("example.main_window"):
    UI.Button("Maximize").click(self.maximize_window)

# In an event handler:
def maximize_window(self, event):
    UI.ref("example.main_window").maximize(True)

A ref participates in the VDOM key. Updating the same key overwrites the registry entry; changing or removing the ref rebuilds the widget. Use constant names rather than names that change during rendering, to preserve native state. Declare refs while building nodes; do not change the name on an already-published node, as its previous registry entry cannot then be cleared by normal destruction. Ref names are not guarded against in-place mutation. Destroying a node removes its entry only if it still owns it. Missing names raise the usual dictionary KeyError. Avoid duplicate names yourself: PUI does not check for collisions, and the most recent update overwrites the entry. Replacement does not clear the old entry before publishing the new one; the later destruction of the old node cannot remove the new entry.

Custom nodes may override __pui_binder__(self) to return a specialized interface. Publication occurs after successful update, not during declaration. Every binder stores its original node in .node. Each successful update registers a new binder; queued commands use binder.node.get_node() to follow reconciliation and skip destroyed nodes. Custom binders should inherit PUI.refs.NodeBinder to preserve this contract. Window updates create a fresh binder in the registry. Retrieve it with ref(name) for each action instead of keeping it across renders; nodes do not store binders. Calls after destruction or replacement raise RuntimeError.

The VDOM key is ancestor|node[:grid:row,column,rowspan,columnspan][#tag=internal_tag][#id=id][#ref=ref], with optional suffixes only when set. The path is relative to the current PUIView. #tag= is the internal tag, while public .tag() remains a debug annotation and does not affect identity.

PUI.ref(name) returns the current binder from the shared registry, without caching. Every backend exports this same function. Missing names raise KeyError. The lookup helper does not add synchronization or make ordinary node methods thread-safe.

Selection binder commands

Tabs and Views expose select(key) on their binder, not on the node. Declare a fixed namespaced .ref(name) and call ref(name).select(key). Commands are queued on the UI thread/event loop, including calls originating there. External State bindings and native tab clicks retain their existing behavior. Obtain binders on the UI thread before passing them to workers. The .node property does not make direct node access thread-safe.

Window binder commands

Desktop Window commands are asynchronous, including when called on the UI thread: returning means the request was queued, not that the window has changed. Obtain the binder with ref(name) on the UI thread and pass it to background workers. This does not make ordinary node methods or registry mutation thread-safe. PySide6 uses a queued signal, wx uses CallAfter, Flet uses its page event loop's call_soon_threadsafe, and Tk uses a Python queue drained on its UI thread every 10 ms (at most 256 callbacks per batch). Tk workers never call after() or other Tk APIs. An active event loop is required; there is no synchronous completion result. A request queued before same-key reconciliation operates on the updated node. Queued requests are discarded after destruction/replacement; submitting through an already-invalid binder raises RuntimeError. Tk cancels its queue timer and clears pending work when the application closes.

fullscreen(enabled: bool), maximize(enabled: bool) and minimize(enabled: bool) request live native state changes without writing State. This is separate from Window's constructor arguments and declarative .maximize()/.fullscreen() setters, which remain initial-only.

Each backend Window overrides __pui_binder__() to return its own binder, whose methods schedule the native backend operations on the UI thread/event loop. The shared helper validates arguments, tracks the current live node and skips queued work whose node has been destroyed. Each update publishes a new binder; no binder cache or separate reference-target object is kept on the node. PySide6, wx, desktop Flet and Tkinter implement these commands. Minimization preserves the restore state: unminimizing should restore the maximized/fullscreen window rather than force normal size. Changing maximize/fullscreen does not intentionally unminimize a window. Native window-manager behavior and available state combinations vary; Tkinter/wx use their platform APIs. Textual and browser windows expose the same methods but log warnings for unsupported commands. See the Web reference for browser limitations. The cookbook's Refs example demonstrates node selection and desktop window commands.

HBox / VBox

HBox(*, inverse=False)
VBox(*, inverse=False)

HBox arranges children left to right and distributes flexible space horizontally. VBox arranges children top to bottom and distributes flexible space vertically. Compact children align vertically in the middle of HBox and to the left of VBox; children that expand on the cross axis can fill it. Alignment applies to widget bounds, not the text inside them. Textual aligns the child group rather than each child individually. See backend alignment details and Web sizing rules.

The keyword-only inverse defaults to False; setting it to True reverses child order. It is declarative: pass a State value and changes update the existing container. Virtual views are transparent to the ordering; nested physical containers keep their own direction. Frozen subtrees apply pending fallback ordering on thaw.

PySide6 uses QBoxLayout direction and Web/Pyodide use CSS flex reversal; native reverse flow can start at the opposite edge, and browser DOM/tab order stays in declaration order. wx, Flet, Tkinter and Textual reorder retained children through DOM synchronization, keeping the container's normal starting edge. This API changes visual order, not text direction or a guaranteed keyboard traversal order.

wx and tkinter apply four-sided padding in top/right/bottom/left order. Weights reset during reconciliation. wx desired width/height also supply minimum-size hints; minimum-only hints do not suppress automatic expansion. Tk converts pixel dimensions to native character/line counts, rounding up using the current font/theme geometry. Generic wx styles and Tk native/theme styles restore when removed.

Examples: HBox cookbook and VBox cookbook.

Grid

Columns and rows follow the Grid priority sizing policy on every backend that implements Grid. Static tracks fit their content; only tracks at the highest nonzero priority on each axis expand. Spans contribute demand to every covered track, hidden cells contribute none, and child weight applies on both axes. Automatic columns use the same policy rather than forcing equal widths.

Grid follows container precedence: children fill their assigned cells and expanded spans. Explicit child dimensions provide minimum sizes rather than preventing cell filling.

Without .columns(), Grid keeps its explicit child .grid(row=..., column=..., rowspan=..., columnspan=...) coordinates. Automatic mode overrides child row/column, preserving spans and declaration order for reconciliation. It is available on PySide6, wx, Tkinter, Web, Pyodide and Textual; Flet Grid remains unsupported.

with Grid().columns(1, dense=None).wideColumns(400, 2).wideColumns(600, 3):
    Label("A").id("a").grid(columnspan=2)
    Label("B").id("b").grid(rowspan=2, columnspan=2)
    Label("C").id("c")  # dense=True in columns() would backfill the first-row hole.

Children can override their base .grid() placement responsively:

.wideGrid(minWidth, *, row=None, column=None, rowspan=None, columnspan=None)
.tWideGrid(minWidth, *, row=None, column=None, rowspan=None, columnspan=None)

TextField(form("text")).grid(row=0, column=0, columnspan=1).wideGrid(
    600, columnspan=2,
).tWideGrid(60, columnspan=2)

Declare .grid() first, then overrides. Compare the nearest physical parent's content width with an inclusive threshold; graphical backends use logical pixels and Textual uses only .tWideGrid() terminal columns. Matching calls apply in declaration order, later values win, and None leaves a field unchanged. Unknown widths use the base declaration; rebuilding below a threshold restores its base values. Responsive values never enter the vnode key, including when id/ref is chained afterwards, so moving/resizing a cell retains its control and editing state. With automatic .columns(), row/column remain ignored; effective spans feed the selected dense placement rule and column spans are clamped to the current column count. Support follows the backend's Grid implementation; Flet Grid remains unavailable.

.columns(n, *, dense=None, expandChildren=True) requires a positive integer. Textual inherits its base column count, dense mode and expandChildren setting unless .tColumns(n, *, dense=None, expandChildren=True) explicitly overrides them, regardless of the order of those two calls. Calling .tColumns(n) sets the terminal dense mode to None, even when columns() specifies another mode.

.wideColumns(minWidth, n, *, expandChildren=None) follows wideLayout: compare the nearest non-virtual parent's available width, use an inclusive threshold, and apply matching calls in declaration order (last matching call wins). Declare a base columns count before breakpoint overrides. Unknown initial geometry uses the base count. Textual ignores pixel-based wideColumns() breakpoints; use .tWideColumns(minWidth, n, *, expandChildren=None) with terminal-cell thresholds instead. A matching breakpoint preserves the current expandChildren setting when omitted (None), or overrides it with True/False; dense remains inherited unless tColumns() sets it explicitly. Terminal overrides take precedence over shared defaults. Graphical backends ignore the terminal declarations. Container size subscriptions use the existing responsive mechanism.

with Grid().columns(1, dense=True).wideColumns(600, 3).tWideColumns(60, 3):
    # Textual inherits one column and dense=True, then uses three columns at 60 cells.
    Label("A").grid(columnspan=2)
    Label("B").grid(columnspan=2)
    Label("C")

expandChildren=True fills available holes after every child's row/column has been assigned. In declaration order, each visible child first grows its columnspan to the right, then its rowspan downward. Expansion requires the whole new edge to be empty, stays within the existing row count and column count, and never moves a child's origin or overlaps another child. Holes that cannot be covered by rectangular expansion remain. Only computed spans change; declared spans and vnode keys remain intact, and disabling expansion restores ordinary placement. Manual Grid placement is unaffected.

Grid().columns(2, expandChildren=False).wideColumns(800, 4, expandChildren=True)
Grid().columns(2, expandChildren=False).tWideColumns(80, 4, expandChildren=True)

The keyword-only dense parameter has three states. None (the default) searches from the previous visible sibling's starting row and never places a later item above that row; it can backfill holes to the left within the same row. True searches from the top-left without that row bound. False keeps the placement cursor moving forward without backfilling earlier holes. True and None can make left-to-right visual order differ from declaration and Tab order. Hidden items retain their controls but occupy no automatic cell. Column spans larger than the current column count are clamped for placement only and restored when the Grid widens; row spans remain intact. This is a tile mosaic on shared row tracks, not independent masonry columns.

Computed cells do not enter vnode keys, so resizing/reflow preserves native controls and editor state. Use stable item IDs when reordering application data. Virtual PUIView children are flattened into the Grid and independent subview updates trigger reflow. Keep explicit desktop/terminal sizing units separate using layout/tLayout. Automatic columns follow the same Grid priority policy as explicit placement. Web/Pyodide tracks with equal expansion weights retain their individual content sizes and share only the extra space equally; they do not force equal intrinsic widths or heights. Native minimum-size hints and rounding can still differ by backend. A spanning cell contributes its size requirement across the tracks it covers.

The existing Grid cookbook shows manually positioned colored tiles. The separate Adaptive Grid cookbook uses muted colors and tall/narrow plus wide cards to leave gaps in four columns. Its 2/3/4-column breakpoints are 384/576/768 logical pixels or 38/58/77 terminal cells, measured against the parent content width. These are 3.2 times the original breakpoints, rounded to whole cells for Textual. With the original order and C shown, blue F lands on row 4 for dense=None (same-row backfill), row 3 for True (earlier-row backfill), or row 5 for False (forward only), counting rows from 1. Narrower demos reduce the column count, so those placements need not differ. The Expand children checkbox toggles the post-placement expansion pass. Tile labels describe their declared spans; expanded spans may be larger. It also demonstrates hidden-item compaction, keyed reordering and a retained editor whose column span changes from one to two at 576 px / 58 terminal columns using wideGrid/tWideGrid.

The ComboBox cookbook includes non-editable/editable controls, disabled examples of both modes, and a destination autocomplete with separate State, explicit editable=True, and distinct labels/airport-code values. Canvas

wx reuses pens, brushes and fonts within a paint callback and skips redundant DC pen/brush setters. Its push()/pop() saves and restores only the native pen, brush and PUI style tracking, with nested scopes supported. Clipping, transforms, fonts and other raw DC state remain the application’s responsibility. Wrap native pen/brush changes in balanced push/pop scopes and pop before resuming PUI helpers; direct DC access is not intercepted. When mixing helpers with raw canvas.dc drawing, set the raw operation's pen/brush explicitly. Text, paths and images retain their local GraphicsContext; native style caches are cleared after each paint, including errors.

PySide6 captures the native pen/brush defaults at the beginning of each paint and reuses matching styles within that frame. Consecutive helpers with identical cached styles skip redundant pen/brush setters. Geometry helpers set their pen/brush directly; they do not save and restore the entire painter for each primitive. Text without a color uses the frame's default pen, and text transforms/fonts and image opacity remain scoped to each call. PySide6 Canvas provides push()/pop() to save and restore native painter state together with PUI style tracking, with nested scopes supported. Wrap raw canvas.qpainter operations in a push/pop scope and pop before returning to PUI drawing. Set raw pen/brush explicitly; helper styles may remain active. Native access is not intercepted: applications are responsible for state consistency when mixing raw operations and helpers within a scope. These methods must be balanced within the paint callback; pop without push raises RuntimeError. All backends expose push()/pop(). On Flet, Tkinter, Web/Pyodide and the unsupported Textual Canvas placeholder, these are compatibility no-ops: they do not save or restore native state. PUI draw calls specify their own styles, so shared painters can use balanced scopes without backend checks. PySide6 and wx provide state stacks and validate scope balance; wx saves only pen/brush and style tracking as described above. Frame caches are discarded when painting finishes, including when the callback raises.

Flet dispatches all seven Canvas callbacks through native GestureDetector events. Coordinates are local logical pixels. Colors

Integer colors are 0xTTRRGGBB: transparency 00 is opaque, FF is transparent. Existing 0xRRGGBB values remain opaque, including black 0. Color(rgb, alpha=1) returns this integer; alpha is opacity from 0 to 1. Invalid RGB integers or nonfinite/out-of-range alpha raise ValueError.

Color(0x336699, alpha=0.5)  # 0x80336699 (8-bit opacity quantization)
Color(0x336699, alpha=0)    # 0xFF336699

Qt, browser and Flet graphics support alpha. wx GraphicsContext supports alpha, and transparent primitives use it; native widgets may ignore opacity. Tk native vector items and widget styles use RGB only; RGBA images preserve alpha. Native widget themes may ignore foreground/background opacity independently of Canvas.

Enums live on the shared Canvas mixin and are accessible through every graphical backend's Canvas. Path commands require PathOp values, not string literals. Web serialization converts enums to protocol values.

    (O.MoveTo, 10, 20),

Explicit IDs survive label changes; keyed moves retain pages and selection. The internal model initially selects the first tab. None or unknown keys display the first available tab without rewriting the requested value; an empty Tabs has no page. .select(None) returns to the first tab. Restoring a removed selected key restores its requested selection.

The cookbook demonstrates both Tabs() with .select() buttons and Tabs(model=...) controlled by optional_state, using both explicit IDs and text fallback. Textual uses native Tabs and ContentSwitcher with TOP/BOTTOM placement; RIGHT/LEFT raises NotImplementedError.

PySide6 applies QTabWidget placement; Tk uses native ttk tabposition style. Flet supports TOP/BOTTOM. Theme/platform appearance can differ.

Flet 1.x uses Tabs/TabBar/TabBarView, supports TOP/BOTTOM, and preserves keyed page selection. Native Container shells apply generic layout parameters. Install with QPUIQ[flet].

PySide6 uses native QTabWidget placement. Tkinter applies ttk tabposition style for TOP/BOTTOM/RIGHT/LEFT; theme/platform appearance may differ. Flet supports TOP/BOTTOM and preserves keyed selection.

wx uses a native Notebook with one content widget or layout per Tab. Keyed pages can be reordered/removed and labels update reactively. Side.Top/Side.Right/Side.Bottom/Side.Left select placement (Side enum only; raw strings and the former Tabs direction constants are not accepted); changing placement remounts the native notebook. wx Label(..., selectable=True) and Text(..., selectable=True) use read-only TextCtrl controls; changing selectability remounts the control.

Stack

Tkinter uses a ttk.Frame with all children in one expanding grid cell; later declarations are lifted above earlier ones. Natural sizing follows the largest child plus its padding. Widgets and nested layouts retain keyed controls across updates/reordering. Spacer does not add a covering layer. Tk controls generally paint opaque backgrounds, so upper controls cover lower ones; transparent text composition is not guaranteed.

wx uses a native Panel with an overlay sizer. Children share the available rectangle with their own padding; the minimum size is the maximum child minimum size. Later declarations are raised above earlier ones. Widgets and nested layouts support keyed updates, reordering and removal. Native hit testing applies: the upper control receives input in its occupied area. Transparent backgrounds depend on the native control and platform; opaque controls cover lower layers, so text overlap may differ from Qt/Web.

Except on Textual, Stack overlays children, with later declarations above earlier ones. See Web Stack for browser layout and hit testing.

On Windows, non-selectable wx labels hosted directly by Stack (including through nested sizers) use generic text painting and compose text layers in declaration order on every repaint. This preserves upper text layers even when Windows repaints transparent siblings in reverse order. Other native controls retain platform-dependent background composition.

PySide6 and Flet have native implementations. Textual uses VBox as a fallback: children are arranged vertically in reverse declaration order (later children above earlier ones), without overlap.

Table

See Web Table for inline editors, commit timing, draft retention, sizing and browser limitations.

TableNode(data, *, display=None, choices=None, prefix='', suffix='', placeholder=None) keeps the raw editable value separate from presentation. display replaces only the displayed value; prefix and suffix surround it in both the cell and its editor and are never written back. Decorations are literal, with no automatic punctuation or spacing: TableNode(100, prefix="Price: $", suffix=" USD") displays Price: $100 USD while editing only 100. placeholder is passed only to an editable cell's native text/choice editor and never affects display or committed data. Boolean editors have no placeholder. Tkinter's Tk 8.6 Entry, wx choice editors, and Qt numeric editors accept the shared API but have no native placeholder.

Textual supports TableNode rows and BaseTableAdapter with native DataTable, literal text, row/column labels, a cell cursor, keyboard navigation and scrolling. Enter opens a Save/Cancel ModalScreen: choices use Select, booleans use Checkbox, and str/int/float/None use Input. Values retain their types, duplicate labels stay distinct, and None is a valid choice separate from no selection. Escape cancels the dialog (or first closes an expanded Select). Draft validation/cancellation follows the Tkinter rules below.

Keyed Textual rows retain the cursor and unchanged drafts. Updates reuse DataTable; row-order/schema changes reset its data and restore the cursor by row key and scroll offsets. autofit=True follows native content sizing; False retains initial column widths in terminal cells. Callbacks follow native activation: clicking a different cell moves the cursor; clicking the highlighted cell or pressing Enter invokes .click(). A double-click activation invokes .dblclick() and opens an editable cell. Navigation and programmatic updates do not invoke callbacks. Cell widgets, drag/drop or automatic header sorting, native column resizing and Qt-style multi-selection are not implemented. See Textual progress for remaining terminal/platform validation.

Tkinter supports TableNode rows and BaseTableAdapter with ttk.Treeview, headers, native row selection, and horizontal/vertical scrollbars. Clicks dispatch cell callbacks. Double-click an editable cell for a Save/Cancel dialog; Enter edits the focused row's last clicked column (initially the first). Choices use a readonly Combobox in the dialog, preserving typed values and duplicate labels. Other editors support str/int/float/bool and None (as text). Invalid numbers or missing choices do not write back. Bindings or .set() callbacks enable editing; choices alone do not. Display stays separate from raw data; ragged cells are inert blanks.

The Tk editing dialog takes modal input and focus once visible; it can be canceled safely if the cell/table disappears before it opens. Keyed Tk rows retain selection and drafts through reordering. Removing a cell/table, changing its value/choices/binding, or making it read-only cancels the draft. Adapter drafts cancel on reconciliation because adapters lack stable row keys. autofit=True measures displayed text; False retains native/user widths. Native selection is row-based. Cell widgets, drag/drop or automatic header sorting, and per-cell styles are not implemented. See Tk progress for pending platform and keyboard checks.

wx uses wx.grid.Grid with TableNode rows or BaseTableAdapter data. Text/numbers edit inline; choices and booleans use native dropdowns. Raw types and duplicate labels are preserved; display text stays separate. Bindings or .set() callbacks enable declarative editing, while missing cells and arbitrary objects without choices are read-only. Invalid numeric edits leave the model unchanged. Headers, selection/scrolling, click/double-click callbacks, and both autofit modes are supported. Redraw/removal cancels unfinished edits; autofit=False preserves native/user column widths. See wx progress for remaining validation and large-data work.

PySide6 refreshes reused adapters with a native model reset, including row/column count changes. A reset may clear selection or an active editor.

Flet supports TableNode rows and BaseTableAdapter using its built-in DataTable. Editable choices cells use Dropdowns; other editable cells open a Save/Cancel dialog. Dialog values support strings, integers, floats, booleans, and None (edited as text). Raw choice values keep their types even with duplicate labels. Display text is separate from raw editing data. Choices alone do not enable editing; missing cells are inert blanks. Choice cells give gestures to the Dropdown, so cell click/double-click callbacks apply to ordinary cells. An explicit choice display value appears as the Dropdown label.

Scheduling callbacks

On the UI thread, call node.get_poster() on a mounted backend node to obtain post(callback, *, delay=0). Pass a zero-argument callable to schedule work on the backend UI/event loop. Optional delay is a finite non-negative number of milliseconds (for example, delay=500), measured from submission; execution may be later when the loop is busy. Timer creation also runs on the UI loop, so posting with a delay is safe from a background thread. No cancellation handle is returned. Obtain the poster before handing it to a background thread; do not look up refs or access native UI from that thread. The application is responsible for stopping background work before the target or application is destroyed. See the Cookbook's Refs page for a button that queues a State update after 500 ms.

Inbound drag and drop

.drop(callback, *args, extensions=None, **kwargs) enables a target. Optional .dragEnter(callback) receives a notification; it is not required for acceptance. Callbacks receive a portable DropEvent, replacing the former raw Qt event.

def dropped(event):
    for file in event.files:
        print(file.name, file.path, file.temporary)
    event.accept()

UI.Label("Drop text files here").drop(dropped, extensions=(".txt",))

Events expose files, text, urls, local x/y coordinates and action (copy, move or link). Each DropFile has name, path and temporary. Call event.accept() explicitly; returning without acceptance rejects the batch. event.reject(reason) supplies a reason, shown as an alert in browsers. Extension matching ignores case; one invalid filename rejects the entire batch. On PySide6/wx, include "/" in extensions to allow directories; extensions=None allows both files and directories. Directories appear in event.files with their original path and temporary=False; PUI does not enumerate or copy their contents. Use pathlib.Path(file.path).is_dir() to distinguish them. Web/Pyodide still reject directories, even with this filter.

PySide6 and wx preserve supported source actions and reference original files (temporary=False); acceptance itself never moves or deletes files. Web and Pyodide support copy only, with temporary=True files in server or virtual storage. Applications must copy/move them to retain them, and may delete them early. Text and URLs create no files.

Supported targets: PySide6 widgets/trees, wx native Window controls, Web and Pyodide DOM controls. wx sizer-only layouts cannot be targets. Tkinter and Flet require external integrations not included here; Textual does not support this API. This does not implement outgoing drags or table row reordering. See the Web and Pyodide references for upload limits and lifecycle.
