Python compatibility

The shared framework and PySide6 backend support Python 3.9. Shared and Qt regression suites pass on Python 3.9.24 with PySide6 6.7.2 on Linux; embedded-host integration and other platforms need separate validation. Optional backends can require newer Python: the supported Flet 1.0.4 runtime requires Python 3.10+. See Python 3.9 compatibility for installation and the repeatable make check-python39 baseline check.

The Qt test runtime is pinned to PySide6==6.7.2 in tests/requirements-python39.txt; make check-python39 rejects a different version.

Backend installation

Installation extras: QPUIQ[pyside6], QPUIQ[wx], QPUIQ[flet], and QPUIQ[textual]. For Tkinter, install plain QPUIQ with native Python/OS Tk support; QPUIQ[tkinter] adds no pip dependency. See installation.

Backend alignment status and pinned PySide6 baselines: wx, flet, tkinter, and Textual. Textual has native headless Views/Tabs checks; broader alignment and terminal validation remain pending. wx, Qt and Tk have native regression coverage; Flet has serialized Session checks and live web Table editing/scrolling checks. Recorded env/ runtimes are PySide6 6.12.0, Tk 8.6, Flet 1.0.4 and Textual 8.2.8. Progress documents list the remaining checks.

Application and view classes

Classes are the recommended API. Import Application and PUIView from the selected backend. Implement content() to declare the UI; initialize local state in setup(), which runs once when the view is first built. Constructors can accept explicit parameters and must call super().__init__().

Application classes


class Example(Application):
    def content(self):
        with Window(title="Example"):
            Label("Hello")

Example().run()

Reusable view classes

On wx, import PUIView from PUI.wx to schedule reactive redraws on the wx GUI queue. Redraw bursts are coalesced; removed views ignore queued work. Native widgets are reused during reconciliation and destroyed with their owner. Removing or replacing a virtual subview destroys its native roots, including controls inside wx sizer layouts. Keyed moves preserve those controls.


class Counter(PUIView):
    def setup(self):
        self.state = State()
        self.state.count = 0

    def content(self):
        with HBox():
            Label(str(self.state.count))
            Button("+").click(self.increment)

    def increment(self, event):
        self.state.count += 1

Deprecated decorators

Each decorator emits DeprecationWarning at its use site when it is applied; creating instances and redrawing existing views do not repeat that warning. Use Python's -Wd option to show deprecation warnings during migration.

@PUI and @PUIApp are deprecated but remain available for existing code. Replace a decorated function with a PUIView or Application subclass and move its body into content(self). Move parameters into an explicit constructor, initialize persistent local state in setup(), and use member event handlers. For example, @PUI def Greeting(text) becomes:


class Greeting(PUIView):
    def __init__(self, text):
        super().__init__()
        self.text = text

    def content(self):
        Label(self.text)

Existing decorator argument forwarding, backend scheduling, and functools.wraps metadata remain supported during deprecation. inspect.signature() displays the builder signature and inspect.unwrap() returns the builder for source inspection. Calling the wrapper still creates a view/application; a builder's return annotation does not describe the wrapper's return value.

Callback Interface

All callback interfaces accept an event object as the first argument. Other args/kwargs will be passed through to the callback function. For example 

def button_cb(event, data):
    print(data)

Button("button").click(button_cb, 1)
will invoke 

button_cb(event, 1)
when the event is emitted.

Widget sizing is automatic by default. PUI assigns each component a preferred size and axis-specific expansion behavior, then maps that policy to the selected backend's native layout system. A TextField expands horizontally but keeps its native height; a Spacer takes flexible space on its container's main axis. Exact dimensions depend on the toolkit, platform, font and theme.

Use .layout() for intentional overrides: width and height provide explicit dimensions or native size hints, weight controls participation in flexible space along the parent layout's main axis, and padding/margin add spacing. Most ordinary controls should not need explicit dimensions merely to fit their container.

Linear-container alignment

The common target is approximate cross-axis centering: HBox vertically centers compact children, and VBox left-aligns them. Expandable children may still fill their available space. This positions widget bounds, not text inside a Label or input; fonts, native dimensions and rounding differ.

Application

Every backend accepts keyword-only Application(title=''). The cookbook sets title="PUI Cookbook". PySide6/wx/Flet retain Application(icon=None, *, title=''); Textual uses Application(*, title=''), and Web/Tkinter retain positional forwarding with Application(*args, title=''). This is startup configuration, not a State binding.

app = MyApplication(title="My app")
app.run()
  • Web: browser page title; see Web application titles.
  • Textual: native App.title and terminal title on mount, including textual-dev launches. Window.title remains ignored.
  • PySide6/wx: native application display name and fallback window titles.
  • Tkinter: hidden root title and fallback visible window titles.
  • Flet: Page title, overridden by an explicit Window.title.

Web and desktop Window(title=None) inherits a nonempty Application title. An explicit Window title, including an empty string, wins. Omitting Application.title preserves existing backend defaults.

Textual uses the existing Rich dependency's public Console.set_window_title on the launch output stream, strips terminal control characters and skips headless mode. Visibility depends on terminal support/settings; the prior title is not restored on exit.

Tkinter configures its theme before creating controls with .tkinter(theme=None). When no theme is specified, Tk keeps its default theme. Select an available native theme with, for example, MyApplication().tkinter(theme="clam"). The theme is initialized once per root; redraws do not reset it.

Applications can load the optional Sun Valley package themselves. Import sv_ttk and call sv_ttk.set_theme("dark", root=self.ui) in your Application subclass's setup(), after the Tk root exists and before content() creates controls. Use "light" for its light variant. Sun Valley mainly styles ttk controls; regular tk controls only benefit from its color scheme. See the runnable Sun Valley dark example:

python -m pip install sv-ttk
python -m examples.tkinter_sun_valley

The Tkinter cookbook uses the same setup() hook to try Sun Valley light, falling back to classic when the optional package is absent. This is cookbook configuration; the backend keeps the native default for other applications.

Closing the last Tkinter Window, removing it without a replacement, or calling Application.quit() ends the main loop and destroys the hidden Tk root, dialogs, timers and pending redraws. With multiple windows, closing one hides it while the others remain open; redraws retain its controls without reopening it. Replacing a window during reconciliation does not quit the application.

wx reactive views use the native GUI queue; import PUI and PUIView from PUI.wx. Redraw bursts are coalesced and removed views ignore queued work. Flet uses its session loop. Tkinter queues redraws and quit outside geometry idle flushes to prevent reconciliation reentry. Application.quit() is also queued on wx. TimelineView timers follow reconciled nodes and stop after removal.

Removing or replacing a virtual subview destroys its native roots, including controls inside wx sizer layouts. Keyed moves preserve those controls.

HBox

Horizontal linear layout container. Children run left to right; flexible space is distributed horizontally. The default alignment target is vertical middle for compact children, while vertically expandable children can fill the height. This aligns widget bounds, not the text inside them.

Web and wx center non-expanding children individually. Textual centers the child group, so different heights can leave smaller children off-center. PySide6 and Flet use native vertical centering; growable Qt controls can fill the height. Tkinter centers TextField/MaskedField vertically, while most other controls stretch. See backend alignment details and Web sizing rules.

wx and tkinter apply four-sided padding in top/right/bottom/left order. Weights reset during reconciliation. wx width/height are minimum-size hints; Tk text dimensions retain native character/line units. Generic wx styles and Tk native/theme styles restore when removed.

VBox

Vertical linear layout container. Children run top to bottom; flexible space is distributed vertically. The default alignment target is horizontal center for compact children, while horizontally expandable children can fill the width. This aligns widget bounds, not the text inside them.

Web and wx center non-expanding children individually. Textual centers the child group, so different widths can leave smaller children off-center. Other backends still differ: Flet aligns left; PySide6 normally fills the width but leaves width-constrained controls at the left; Tkinter normally fills the width. Combobox

The ComboBox cookbook includes read-only/editable controls and a destination autocomplete with separate State, explicit editable=True, and distinct labels/airport-code values. Suggestion filtering depends on the native backend; see Web selection controls for browser suggestions and commit timing.

ComboBox(editable=False, index_model=None, text_model=None, *, enabled=True) accepts a keyword-only enabled flag on PySide6, wx, Flet, tkinter and Web. Disabling prevents user selection/typing while preserving values and allowing programmatic model updates. Tk uses native ttk.Combobox and idle notification to avoid double-reporting selection text.

wx safely handles empty/invalid selections and refreshes item labels. Changing native editability remounts the control. Flet uses native Dropdown and Tkinter uses ttk.Combobox.

Canvas

wx reuses pens, brushes and fonts within a paint callback and sets geometry styles directly. When mixing helpers with raw canvas.dc drawing, set the raw operation's pen/brush explicitly. Text, paths and images retain their local GraphicsContext; native style caches are cleared after each paint, including errors.

PySide6 captures the native pen/brush defaults at the beginning of each paint and reuses matching styles within that frame. Geometry helpers set their pen/brush directly; they do not save and restore the entire painter for each primitive. Text without a color uses the frame's default pen, and text transforms/fonts and image opacity remain scoped to each call. When mixing helpers with raw canvas.qpainter operations, set the raw operation's pen/brush explicitly; helper styles may remain active. Frame caches are discarded when painting finishes, including when the callback raises.

See Web Canvas for browser rendering, command diffs, pointer/wheel events, text semantics, command-error handling, limits and performance measurements. Web and Pyodide log individual drawing exceptions in the browser console and skip that command.

The HeavyCanvas cookbook uses a static PUIView class and standard-library seeded random data. Its English chart shows OHLC candles, 20-session Bollinger bands (two population standard deviations), volume, smoothed stochastic K/D (9-session range, smoothing 3) and Wilder RSI 14. It defaults to 1,000 weekday sessions, with 1,000/3,000/5,000/7,500/10,000/15,000/20,000/25,000/30,000 presets producing roughly 9,000–270,000 individual Painter commands per frame. Regenerate advances the seed. Vertical wheel input zooms around the pointer: up keeps 80% of visible sessions, down expands by 1.25x, rounded and bounded to 20 sessions through the full dataset. Only direction is used, with no pixel-to-angle conversion. Price and volume axes autoscale to visible rows. Reset zoom, changing the preset or Regenerate restores the full range. Visible session counts, zoom and draw-call estimates are displayed. Generated data and indicators are cached through zoom/hover; visible row ranges and axis limits are reused between zoom changes. The painter redraws all panels, a crosshair and a tooltip, producing large command replacements on zoom and small tooltip deltas on hover. The scrollable chart requests a 720-logical-pixel height and uses its measured drawing width. Tkinter uses its allocated drawing size but lacks native Canvas hover/wheel events, so its controls update a static chart without crosshair/tooltips or wheel zoom.

Flet canvases with .layout(weight=1) fill their available native drawing space. Paint callbacks wait until both dimensions are positive and finite, so the first callback can fit a drawing. Identical resize notifications do not repaint; model redraws still invoke the current painter.

Flet 1.x uses native Text/Path/Rect/Oval, including cubic paths and rotated text. Canvas image crop/resources and text height clipping remain pending. Native pointer/gesture behavior is described under Callbacks.

wx includes ImageResource.load/crop/scale, loadImage/drawImage source rectangles and opacity, cubic paths, enter/leave, and wheel modifiers. Source image opacity is preserved; native wheel pixel deltas are zero when unavailable. Queued paints after removal are ignored. Tk Canvas source adds native polygon/rectangle/ellipse and text size/color/rotation/anchors; cubic paths, images, and text height clipping are incomplete.

Example 

def painter(canvas):
    # Physical pixels per logical canvas pixel; 1.0 when unavailable.
    pixel_density = canvas.pixel_density
    canvas.drawText(x, y, text, w=None, h=None, size=12, color=None, rotate=0, anchor=Anchor.LEFT_TOP)
    canvas.drawLine(x1, y1, x2, y2, color=0xFF0000, width=1)
    canvas.drawPolyline([x1, y2, ..., xn, yn], color=0xFF0000, width=1)
    canvas.drawCubicBezier(start, control1, control2, end, color=0xFF0000, width=1)
    canvas.drawRect(x1, y1, x2, y2, fill=0xFF0000, stroke=0x00FF00, width=1)
    canvas.drawShapely(shape, fill=0xFF0000, stroke=0x00FF00, width=1)

Canvas(painter)

Canvas drawing coordinates, canvas.width and canvas.height use logical pixels. canvas.pixel_density reports the number of physical display pixels per logical pixel and is refreshed before painting where supported. Use it to select the resolution of raster content for HiDPI displays. Its fallback value is 1.0.

drawCubicBezier() is available on PySide6, wx, Flet and Web. start, control1, control2, and end are (x, y) coordinate pairs defining a cubic Bézier curve.

wx supports ImageResource.load(path), .crop(x, y, width, height), .scale(width, height, keepAspectRatio=True, quality=0), canvas.loadImage(path) and:

canvas.drawImage(resource, x=0, y=0, width=None, height=None, src_x=0,
                 src_y=0, src_width=None, src_height=None, opacity=1.0)

Image operations return new resources; opacity does not mutate the source. wx wheel events provide angular deltas and modifiers; pixel deltas are zero.

Callbacks

Flet dispatches all seven Canvas callbacks through native GestureDetector events. Coordinates are local logical pixels. Left/right press, drag and release continue outside the Canvas; middle-button taps use the tertiary tap recognizer. Hover has button=MouseButton.NONE, while recognized drags report their button. Registration and callbacks update on redraw; removed canvases ignore queued events, and drawing-only canvases omit the gesture wrapper.

Flet follows native gesture timing and thresholds. Double-click is primary-button only and fires after recognition at the second press position. Cancelled or consumed presses report mouseup with cancelled=True at the last reported position; normal releases have cancelled=False. Clear drag state on cancellation without treating it as a completed edit. Middle-button dragging, extra buttons and simultaneous-button tracking are unavailable.

Wheel x_delta/y_delta contain pixel deltas, positive left/up to match PySide6. Angular h_delta/v_delta stay 0; pixels are never converted to angles. modifiers=None means Flet did not report modifiers. Consumers using only v_delta need an application-level pixel-delta path.

Splitter(vertical=False)

wx composes native SplitterWindow controls for any number of panes. Extra children nest in the right pane, A | (B | C), or the bottom pane with vertical=True. Moving an earlier sash resizes the remaining group. Declare nested Splitter blocks explicitly for another grouping; there is no automatic nesting-direction option.

Widgets, layouts, and nested splitters can be panes. Keyed moves retain controls and state; ordinary redraws retain sash positions. Changes to pane order/count or orientation redistribute space equally, and later window resizes share size changes equally among panes. A one-pixel minimum prevents native dragging or double-clicking from unsplitting declared content. Empty and single-pane splitters have no sash.


with Splitter():
    Label("Left")
    Label("Right")

Views

See Web Views and Tabs for browser page retention and keyboard behavior.

Views(model=None) displays one child view without navigation controls. Each direct child needs a unique non-empty string .id(). Widgets, layouts, and PUIView instances are supported; multiple root controls in one view are grouped vertically. Declared views stay alive while hidden; removing a declaration destroys that view.

The optional model is a writable binding containing the selected ID. Without one, Views owns an internal model initialized to None and preserved across redraws. .select(key) updates the model and schedules a redraw; .select(None) clears the selection. None or an undeclared ID shows an empty container without rewriting the model. Keyed reordering retains views and selection; older handles follow reconciliation, and removed containers ignore selection requests.

with Views() as views:
    EditorView().id("editor")
    SettingsView().id("settings")

# In an event handler:
views.select("editor")

Use Views(model=state("current_view")) for external state. Views supports PySide6 through QStackedWidget, tkinter through retained ttk.Frame pages, Textual through ContentSwitcher, and wx through Simplebook; remaining native validation is tracked in the backend progress documents.

The cookbook Views page demonstrates both .select() with an internal model and selection by assigning a State field, with a stateful editor in each container.

State bindings preserve None, so .select(None) also clears an external model.

Flet Views is deferred: its current native controls do not provide both programmatic-only switching and guaranteed retention of inactive native pages.

Tabs and Tab

See Web Views and Tabs for browser headers, keyboard navigation and retained pages.

Tabs(tabposition=Tabs.NORTH, model=None) uses an internal selection model by default. Pass model=optional_state("selection") for an external binding. Native tab clicks, .select(key), and bound-state assignments share the selection; older handles follow redraws. All five backends support this model.

Selection uses each Tab's explicit .id(), otherwise its text. The first match wins duplicate IDs/text, including clicks on later duplicates. Explicit IDs survive label changes; keyed moves retain pages and selection. The internal model initially selects the first tab. None or unknown keys display the first available tab without rewriting the requested value; an empty Tabs has no page. .select(None) returns to the first tab. Restoring a removed selected key restores its requested selection.

The cookbook demonstrates both Tabs() with .select() buttons and Tabs(model=...) controlled by optional_state, using both explicit IDs and text fallback. Textual uses native Tabs and ContentSwitcher with NORTH/SOUTH placement; EAST/WEST raises NotImplementedError.

PySide6 applies QTabWidget placement; Tk uses native ttk tabposition style. Flet supports NORTH/SOUTH. Theme/platform appearance can differ.

Flet 1.x uses Tabs/TabBar/TabBarView, supports NORTH/SOUTH, and preserves keyed page selection. Native Container shells apply generic layout parameters. Install with QPUIQ[flet].

PySide6 uses native QTabWidget placement. Tkinter applies ttk tabposition style for NORTH/SOUTH/EAST/WEST; theme/platform appearance may differ. Flet supports NORTH/SOUTH and preserves keyed selection.

wx uses a native Notebook with one content widget or layout per Tab. Keyed pages can be reordered/removed and labels update reactively. Tabs.NORTH/SOUTH/EAST/WEST select placement; changing placement remounts the native notebook. wx Label(..., selectable=True) and Text(..., selectable=True) use read-only TextCtrl controls; changing selectability remounts the control.

Example 

with Tabs():
    with Tab("Tab 1"):
        Label("Tab Content 1")
    with Tab("Tab 2"):
        Label("Tab Content 2")

Table

See Web Table for inline editors, commit timing, draft retention, sizing and browser limitations.

TableNode(data, *, display=None, choices=None, prefix='', suffix='', placeholder=None) keeps the raw editable value separate from presentation. display replaces only the displayed value; prefix and suffix surround it in both the cell and its editor and are never written back. Decorations are literal, with no automatic punctuation or spacing: TableNode(100, prefix="Price: $", suffix=" USD") displays Price: $100 USD while editing only 100. placeholder is passed only to an editable cell's native text/choice editor and never affects display or committed data. Boolean editors have no placeholder. Tkinter's Tk 8.6 Entry, wx choice editors, and Qt numeric editors accept the shared API but have no native placeholder.

Textual supports TableNode rows and BaseTableAdapter with native DataTable, literal text, row/column labels, a cell cursor, keyboard navigation and scrolling. Enter opens a Save/Cancel ModalScreen: choices use Select, booleans use Checkbox, and str/int/float/None use Input. Values retain their types, duplicate labels stay distinct, and None is a valid choice separate from no selection. Escape cancels the dialog (or first closes an expanded Select). Draft validation/cancellation follows the Tkinter rules below.

Keyed Textual rows retain the cursor and unchanged drafts. Updates reuse DataTable; row-order/schema changes reset its data and restore the cursor by row key and scroll offsets. autofit=True follows native content sizing; False retains initial column widths in terminal cells. Callbacks follow native activation: clicking a different cell moves the cursor; clicking the highlighted cell or pressing Enter invokes .click(). A double-click activation invokes .dblclick() and opens an editable cell. Navigation and programmatic updates do not invoke callbacks. Cell widgets, drag/drop or automatic header sorting, native column resizing and Qt-style multi-selection are not implemented. See Textual progress for remaining terminal/platform validation.

Tkinter supports TableNode rows and BaseTableAdapter with ttk.Treeview, headers, native row selection, and horizontal/vertical scrollbars. Clicks dispatch cell callbacks. Double-click an editable cell for a Save/Cancel dialog; Enter edits the focused row's last clicked column (initially the first). Choices use a readonly Combobox in the dialog, preserving typed values and duplicate labels. Other editors support str/int/float/bool and None (as text). Invalid numbers or missing choices do not write back. Bindings or .set() callbacks enable editing; choices alone do not. Display stays separate from raw data; ragged cells are inert blanks.

The Tk editing dialog takes modal input and focus once visible; it can be canceled safely if the cell/table disappears before it opens. Keyed Tk rows retain selection and drafts through reordering. Removing a cell/table, changing its value/choices/binding, or making it read-only cancels the draft. Adapter drafts cancel on reconciliation because adapters lack stable row keys. autofit=True measures displayed text; False retains native/user widths. Native selection is row-based. Cell widgets, drag/drop or automatic header sorting, and per-cell styles are not implemented. See Tk progress for pending platform and keyboard checks.

wx uses wx.grid.Grid with TableNode rows or BaseTableAdapter data. Text/numbers edit inline; choices and booleans use native dropdowns. Raw types and duplicate labels are preserved; display text stays separate. Bindings or .set() callbacks enable declarative editing, while missing cells and arbitrary objects without choices are read-only. Invalid numeric edits leave the model unchanged. Headers, selection/scrolling, click/double-click callbacks, and both autofit modes are supported. Redraw/removal cancels unfinished edits; autofit=False preserves native/user column widths. See wx progress for remaining validation and large-data work.

PySide6 refreshes reused adapters with a native model reset, including row/column count changes. A reset may clear selection or an active editor.

Flet supports TableNode rows and BaseTableAdapter using its built-in DataTable. Editable choices cells use Dropdowns; other editable cells open a Save/Cancel dialog. Dialog values support strings, integers, floats, booleans, and None (edited as text). Raw choice values keep their types even with duplicate labels. Display text is separate from raw editing data. Choices alone do not enable editing; missing cells are inert blanks. Choice cells give gestures to the Dropdown, so cell click/double-click callbacks apply to ordinary cells. An explicit choice display value appears as the Dropdown label.

Keyed TableNode rows/cells retain drafts on reorder. Removing a cell/table, changing its raw value, or disabling editing cancels its draft. Adapter dialogs cancel on table reconciliation because adapters have no stable row keys. Native horizontal/vertical scrolling is provided; headers scroll with the data. Only content sizing (autofit=True) is supported; autofit=False raises NotImplementedError. Qt cell selection, additional editor types, and paging remain outside this implementation. See Flet progress.

Tree

Single column tree widget

wx uses DataViewCtrl with TreeNode declarations or BaseTreeAdapter data. The content column autosizes after model updates. Keyed nodes and stable adapter objects retain selection/expansion across redraws, reordering, relabeling, and adapter moves. Node click/double-click callbacks receive None; expand/collapse callbacks have no event argument. Adapter callbacks receive the node object. expandAll(), collapseAll(), and expandable(enabled) work before mounting and on a live Tree; disabling user expansion still permits imperative changes. Backend alignment status

Flet alignment status

The backend targets Flet 1.x (tested with 1.0.4); install with pip install 'QPUIQ[flet]'. It uses ft.run, Button(content) and Tabs/TabBar/TabBarView. Reactive FView/PUI redraws queue on the session loop and commit one page update after reconciliation. Native Container shells apply weights, dimensions, padding/margins and background; text styles reset when omitted. Window uses Page.window with initial-only flags and imperative methods.

Live web-client smoke checks cover counter updates, editor commits, Tabs, fixed-size Canvas drawing, weighted Canvas initial fit/resizing and Table editing. Scroll interaction and broader visual checks remain pending. See Flet progress.

Tkinter alignment status

Tkinter reuses the native interpreter, coalesces subview redraws, resolves retired controls, emits TextField event values, rebinds/suppresses traces and deduplicates commits. Checkbox/RadioButton update labels and clicks; Tabs uses native destruction. HBox/VBox apply four-sided grid padding and reset removed weights/styles. Application.quit() requests native teardown. Redraws and quit run outside geometry idle flushes, preventing reentrant reconciliation.

The recorded baseline includes twelve native regression checks and all 17 then-supported cookbook pages in the local env/ runtime. Text widgets still use native character/line sizing units; pixel-dimension wrappers need an agreed design. The Canvas cookbook skips cubic drawing on Tkinter. Broader resize and platform checks remain open; see Tkinter progress.

Textual alignment status

Views and Tabs have native headless interaction tests on Textual 8.2.8. Text applies foreground/background colors, including the cookbook's fixed dark code palette, and restores theme colors when styles are removed. Lifecycle, reconciliation, input, layout and scroll gaps, plus broader runtime and terminal validation, are tracked in Textual progress. Matrix entries identify native mappings, not completed parity.
